# コーヒーサバイバル Constitution

## Core Principles

### I. PC 専用

このゲームは PC のブラウザ専用とする。

- 操作はキーボードとマウスだけを前提にする（移動は WASD / 矢印キー、決定は Space / Enter / クリック）。
- スマホ向けの対応は MUST NOT 追加しない。具体的には、タッチ操作、仮想スティック、画面上の操作ボタン、
  狭い画面幅への合わせ込み、ホーム画面追加用の Web App Manifest やモバイル向けメタタグを指す。
- 仕様・確認の対象は、PC の画面サイズ（目安として幅 1000px 以上）に限る。

理由：対応する環境を絞り、1 つの遊び方の完成度を上げるため。

### II. ビルド不要・外部ライブラリなし

- ゲームは、ブラウザが直接読める JavaScript（ES Modules）と Canvas 2D だけで動かす。
- ビルド工程（バンドラ、トランスパイラ）や、実行時に読み込む外部ライブラリを MUST NOT 導入しない。
- ローカルの簡易サーバ（例：`python3 -m http.server`）でそのまま遊べる状態を、常に保つ。

理由：誰でもすぐ起動して確認でき、壊れる部品を増やさないため。

### III. 調整する数値は設定に集める

- ゲームバランスや見た目に関わる数値（速さ、ダメージ、出現間隔、色、文言など）は、
  設定ファイル（`src/config.js` の `CONFIG`）に MUST まとめる。
- 処理の中に、調整対象の数値を直接書かない。

理由：仕様の見直しや微調整を、コードの深い所を読まずに設定 1 か所で行えるようにするため。

### IV. 世界観は「珈琲 × 眠気」で統一する

- プレイヤー側（攻撃・回復・アイテム）は珈琲にちなんだもの、敵側は眠気にちなんだものとして
  名前と見た目を MUST 揃える。
- 画面に出る文言は日本語にする。

理由：遊ぶ人が、ルールを世界観から直感的に理解できるようにするため。

### V. develop で開発し、main は安定版にする。1 機能 = 1 ブランチ = 1 PR

- `develop` は普段の開発の場所、`main` は遊べる状態が確認できた安定版の置き場所とする。
- 新しい機能は、`develop` から専用のブランチを作って進め、`develop` への PR にする。
- 1 つの PR には 1 つの機能だけを入れる。
- 別の機能に依存する場合に限り、その機能のブランチの上に積み重ね、PR の説明にマージの順番を書く。
- `main` には直接コミットしない。`develop` で遊べることを確認できた区切りで、`develop` → `main` の PR を作って反映する。

理由：変更の目的をはっきりさせ、レビューとやり直しを簡単にするため。また、作業途中の変更が
安定版に混ざらないようにするため。

**一時的な例外（2026-10-20〜2026-10-23）**：この期間は、機能ごとのブランチと PR を作らず、
`develop` に直接コミット・プッシュして作業する（2026-10-21 までは `main` に直接コミットしていた）。
コミットは今までどおり 1 つの変更ごとに分け、内容が分かるメッセージを付ける。期間が終わったら、
上の原則に戻す。

## 技術的な制約

- 描画：HTML5 Canvas 2D（1 枚の canvas に全画面で描く）
- 言語：素の JavaScript（ES Modules）、HTML、CSS
- 対象ブラウザ：PC 版の最新の Chrome / Edge / Safari / Firefox
- ゲームの進行はフレームごとの更新処理で行い、1 フレームで進める時間には上限を設ける
  （タブを離れたあとに時間が一気に進まないようにするため）

## 開発の流れ

1. 機能を追加・変更するときは、`specs/` の仕様書を先に更新し、内容を確認してから実装する。
2. 実装後は、ブラウザで実際に動かして確認する（自動操作のヘッドレスブラウザを使ってもよい）。
   確認する項目は、変更した機能の操作、既存の操作（移動・ポーズ・リトライ）、コンソールにエラーが出ていないこと。
3. PR の説明には、変更内容と、行った動作確認を書く。

## Governance

- この憲法は、ほかの慣習や個別の判断より優先する。
- 変更するときは、変更の理由をこのファイルに残し、バージョンを上げる。
  - MAJOR：原則の削除や、意味が変わる書き換え
  - MINOR：原則や節の追加、内容の大きな拡張
  - PATCH：言い回しや誤字の修正
- PR のレビューでは、変更がこの憲法に沿っているかを確認する。
