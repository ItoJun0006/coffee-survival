# Feature Specification: 定期タスクが途中で止まったら、次の回で続きから再開する

**Feature Branch**: `034-routine-resume`

**Created**: 2026-10-23

**Status**: Implemented（ルーティンの決まりとして使う）

**Input**: User description: "5 時間の定期タスクを行なっている時に使用量が足りなくなった場合は、次の作業のときに中断された作業を再開するように仕様書に書いてください"

## Clarifications

### Session 2026-10-23

- Q: どのルーティンに当てはめるか？ → A: 「8 時間ごとのタスク（最大 3 つ）」（2:40・10:40・18:40）。2026-10-30 に、5 時間ごと（2:40・7:40・12:40・17:40・22:40）から 8 時間ごとに変えた
- Q: 途中で止まったことを、次の回はどうやって知るか？ → A: 作業を始めるときに「作業中メモ」（`specs/backlog/routine-progress.md`）に書いてプッシュしておき、終わったら消す。次の回の始めにメモが残っていれば、途中で止まったと分かる
- Q: 書きかけのコードはどうするか？ → A: ゲームが壊れたままの変更は develop に入れない。区切りごとに作業用のブランチ `routine_wip_<タスク番号>` にプッシュしておき、次の回はそこから続ける

## 例え

料理の途中で火を止めて帰るときに、「鍋に下ごしらえ済みの野菜あり。次は味付けから」と冷蔵庫にメモを貼っておくのと同じ。次に来た人は、メモを見て続きから作れる。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: タスクを始めるとき、`specs/backlog/routine-progress.md` の「作業中」の表に、タスクの番号・始めた日時・作業用のブランチ名・終わった手順・次にやる手順を書いて、develop にプッシュしなければならない。
- **FR-002**: 作業の区切り（手順が 1 つ終わるごと）に、作業中の変更を `routine_wip_<タスク番号>` ブランチにコミット・プッシュし、メモの「終わった手順」「次にやる手順」を書き足さなければならない。動作確認が通った変更だけを develop に入れる。
- **FR-003**: タスクが終わったら、作業用のブランチの変更を develop に取り込み、メモの行を「作業中」の表から消して「終わったもの」の表に移さなければならない（作業用のブランチは消さずに残してよい）。
- **FR-004**: 毎回の始めに、まずメモの「作業中」の表を見て、行が残っていれば、新しいタスクより先にその続きを進めなければならない。続きは、作業用のブランチを取り込み、メモの「次にやる手順」から始める。続きを進めたタスクも、その回の最大 3 つに数える。
- **FR-005**: 前の回の書きかけがチャットの作業フォルダに残っていて、メモの作業中のタスクと同じものなら、捨てずに作業用のブランチへコミットしてから続ける。メモにないものは、今までどおり退避（`git stash`）して報告に書く。
- **FR-006**: 続きから再開したときは、報告に「前の回が途中で止まったので、続きから再開した」と、どこから再開したかを書かなければならない。
- **FR-007**: 同じタスクが 3 回続けて途中で止まったら、それ以上は続けず、メモに「止まりやすい」と書いて、ユーザーに分け方を相談する。
